# SDD 规格生命周期

SDD 规格生命周期，是把一次 AI 辅助变更从模糊想法推进到经过测试的代码、归档决策和更完善的未来项目规则的五阶段循环。

## 五个阶段

1. **规划（Plan）**——把想法转化为结构化提案和实施计划。
2. **对齐（Align）**——挑战歧义、边界情况、约束和有争议的决策。
3. **执行（Execute）**——依据已批准规格，实现一个边界明确的功能。
4. **测试（Test）**——验证单元、集成和回归行为。
5. **归档（Archive）**——把当前事实合并进持久规格，并保留决策历史。

原文认为，对齐和归档是最常被跳过的阶段。只有规划而没有对齐，会留下隐藏假设；只有实现而没有归档，会让下次会话重复旧推理和旧错误。

## 两层规格

SDD 需要两种不同的记录：

| 层级 | 生命周期 | 内容 |
| --- | --- | --- |
| 规则层 | 长期 | 项目常量、可复用能力、约定、已知工具、失败策略。 |
| 变更层 | 单次变更 | 变更缘由、设计决策、需求增量、任务、执行记录、经验。 |

规则层可以存在于记忆文件、技能和规范能力规格中。变更层应有独立的具名或带日期目录，并在完成后归档。只保留规则会丢失具体决策的历史；只保留变更则迫使未来工作重新发现稳定的项目知识。

## 归档即学习

归档不是清理文件，而是闭合知识反馈循环：

1. 使用当前规则实现变更。
2. 审阅暴露一条缺失的项目特定约束。
3. 将经验记录到变更归档中。
4. 把反复出现的经验提升为记忆文件、技能、钩子或规范规格。
5. 下一次变更从累积后的规则层开始。

这让生命周期与 [AI 知识工程反馈循环](/wiki/concepts/ai-knowledge-engineering-feedback-loop)相连。只有每次完成的变更都能改善未来上下文，SDD 才会产生复利。

## 能力绑定

原文提出用稳定的能力名称作为主干，连接提案、变更特定的需求增量和当前规范规格。这样，关系变得机械且可搜索，而不必依赖散文相似度。

例如，一个能力标识符可以连接：

- 声明受影响能力的提案；
- 包含新增或修改需求的变更目录；
- 归档时更新的规范规格；
- 描述项目特定实现规则的可复用技能。

## 失效模式

- 写完规格后把它当成静态文档，而不是生命周期。
- 尚未对齐就应用第一版草案。
- 在一次执行会话中混入多个无关功能。
- 实现后才添加测试，因而错过预期行为契约。
- 只归档文件，却不把可复用经验提升到规则层。
