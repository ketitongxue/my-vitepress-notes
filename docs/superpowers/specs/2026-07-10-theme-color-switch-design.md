# 主题颜色切换设计说明

日期：2026-07-10

## 目标

在保持“AI 纪元”现有深色视觉为默认体验的前提下，增加可切换的亮色主题。主题选择由 VitePress 原生外观能力管理，用户切换后记住选择，并覆盖首页、知识库、文章和问答等所有公开页面。

## 范围

本次包含：

- 导航栏中的 VitePress 原生深浅主题切换控件。
- 首次访问默认深色，后续访问恢复用户上次选择。
- 亮色与深色两套语义颜色变量。
- 首页卡片、知识库卡片、导航背景、问答表单和错误状态的双主题适配。
- 深浅主题下的颜色对比度、构建和持久化配置测试。
- 直接追加到现有 `feature/site-design-refinement` 分支及 PR #13。

本次不包含：

- 第三套主题或自定义主题选择面板。
- 跟随系统作为首次访问默认值。
- 用户自定义颜色、字体或字号。
- 修改 Worker、知识库发布、检索、配额或限速逻辑。

## 交互行为

- VitePress `appearance` 使用 `dark`：没有保存记录时以深色启动，但允许用户切换。
- 切换控件使用 VitePress 默认导航栏位置、图标、键盘交互和状态管理。
- 主题选择使用 VitePress 内置存储机制持久化，不增加独立的本地存储键。
- 页面导航和刷新后继续使用保存的主题。
- 首屏主题类由 VitePress 注入，避免先显示亮色再跳到深色的闪烁。
- 控件的中文标签为“主题颜色”。

## 颜色系统

所有自定义组件只引用语义变量，不直接判断主题状态。

## 样式结构

- `:root` 定义亮色变量，`.dark` 覆盖为现有深色变量。
- 新增站点语义变量用于卡片渐变、品牌色上的文字和阴影，避免在组件样式中保留深色十六进制常量。
- `.VPFeature`、知识库卡片、问答对话区、问答输入区、导航半透明背景都从变量派生。
- 错误提示继续分别使用现有亮色和深色错误变量。
- 代码块、侧边栏、搜索、目录和默认按钮由 VitePress 自带变量自动适配。
- 不改变布局、间距、圆角、标题层级或移动端断点。

## 可访问性

- 使用 VitePress 原生按钮语义和键盘操作，不实现仅鼠标可用的自定义开关。
- 控件应具有可理解的中文标签和可见焦点状态。
- 主文字和品牌链接在各自背景上的对比度至少达到 WCAG AA 4.5:1。
- 大号品牌标题和按钮文字至少达到对应的大文字或控件对比度要求。
- `prefers-reduced-motion` 规则继续生效；主题切换不新增大范围动画。

## 测试与验收

- 配置测试确认 `appearance` 为 `dark`，不再使用 `force-dark`。
- 测试确认主题标签为“主题颜色”。
- 样式测试确认亮色变量位于 `:root`、现有深色变量位于 `.dark`，关键组件不再使用深色硬编码背景。
- 颜色测试计算主文字、次文字、品牌链接及品牌按钮文字的对比度。
- 运行完整 `npm test`、Wiki/Finance 验证、Worker 测试、VitePress 构建和安全扫描。
- 在可用的浏览器预览环境中检查首页、AI 知识库、金融知识库、文章页和问答页的深浅主题以及 390 × 844 手机布局。

## 成功标准

- 首次访问仍显示当前深色风格。
- 导航栏提供深浅主题切换，并在刷新后保留选择。
- 亮色主题覆盖所有核心页面，没有深色卡片、黑色输入框或不可读文字残留。
- 两套主题的关键文字和按钮对比度通过自动化检查。
- 现有路由、内容、问答行为、发布流程和额度策略不变。
