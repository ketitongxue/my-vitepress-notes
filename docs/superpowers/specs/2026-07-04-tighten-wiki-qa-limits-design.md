# Wiki 问答限额收紧设计

## 目标

降低公开问答功能的 DeepSeek 调用成本，同时保留现有匿名访问、检索和流式回答体验。

生产限额调整为：

- 每个匿名 IP 每 60 秒最多 3 个有效请求。
- 每个匿名 IP 每个 UTC 日期最多 5 次可靠召回答题。
- 全站每个 UTC 日期最多 10 次可靠召回答题。

## 方案

沿用现有两层限额架构，不新增存储或迁移：

1. Cloudflare Rate Limiting binding 从 `5/60s` 改为 `3/60s`。
2. SQLite Durable Object 的配置值从每 IP 每日 30、全站每日 50，分别改为 5 和 10。
3. HMAC 匿名访客键、UTC 换日、原子预留和并发硬上限逻辑保持不变。

## 计数语义

- 非法 Origin、非法 JSON 和无效请求不进入限速计数。
- 通过输入校验的请求先进入每 60 秒限制。
- 无可靠召回的请求计入 60 秒限制，但不占用每日额度，也不调用 DeepSeek。
- 有可靠召回的请求先原子预留每日额度，再调用 DeepSeek。
- DeepSeek 调用失败不退还每日额度，因为请求已产生潜在成本。

## 用户反馈

现有错误码保持兼容：

- `RATE_LIMITED_MINUTE`：该匿名 IP 在 60 秒内已达到 3 次。
- `DAILY_VISITOR_LIMIT`：该匿名 IP 当日已达到 5 次。
- `DAILY_GLOBAL_LIMIT`：全站当日已达到 10 次。

前端继续使用现有中文错误映射，不改变页面结构。

## 配置与测试

修改范围：

- `wrangler.jsonc` 中的三个限额值。
- README 中的生产限额说明。
- Wrangler 配置、API 编排和文档契约测试中的对应期望值。

验证要求：

- 配置测试断言 `3/60s`、每 IP 每日 5、全站每日 10。
- 每日额度边界测试覆盖第 5/6 次和第 10/11 次。
- 完整 `npm test`、Wrangler dry-run 和安全扫描通过。
- 部署后线上错误拒绝和正常问答不回归。

## 不在范围内

- 不实现滚动一小时窗口。
- 不改变检索阈值、模型、回答长度或会话历史。
- 不清空当前 UTC 日期已经存在的 Durable Object 计数；新配置部署后按更低上限立即判断。
