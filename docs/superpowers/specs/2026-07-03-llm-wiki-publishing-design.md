# LLM Wiki 中文发布设计

## 目标

将 `llm_wiki` 的公开知识层发布到 VitePress 网站，形成可导航、可搜索的中文知识库。`llm_wiki` 仍是唯一知识源；网站仓库只保存经过筛选和翻译的发布副本。

## 范围

首批发布以下三个目录中的全部页面：

- `entities/`
- `concepts/`
- `comparisons/`

不得发布：

- `raw/`
- `queries/`
- `log.md`
- `SCHEMA.md`
- `purpose.md`
- 原始来源路径、本地绝对路径或其他内部工作信息

## 方案选择

采用生成式中文镜像。同步脚本读取外部 Wiki，计算源文件哈希并生成变更清单；新增或变化的页面由 Codex 翻译和校对后进入网站。该方案不需要翻译 API，也不会让网站副本成为第二个独立知识源。

未采用的方案：

- 复制后独立维护：实现简单，但内容会逐渐与 Wiki 不一致。
- Cloudflare 构建时读取 Wiki：需要跨仓库权限和自动翻译服务，增加费用、隐私风险和运维复杂度。

## 内容结构

公开页面生成到：

```text
docs/wiki/
├── index.md
├── entities/
├── concepts/
└── comparisons/
```

网站导航增加“知识库”入口。知识库首页用中文列出实体、概念和对比分析。页面 URL 保留英文文件名作为稳定 slug，标题、摘要、正文和导航文字使用中文。

VitePress 的本地搜索应索引全部公开 Wiki 页面。移动端沿用现有主题的侧边栏和正文布局。

## 发布数据模型

每篇公开页面仅保留以下元数据：

- 中文标题
- 页面类型
- 标签
- 创建日期
- 更新日期

`sources` 字段必须删除。正文中的 `[[page]]` 和 `[[page|label]]` 转换为指向公开 slug 的普通 Markdown 链接。指向未发布页面的链接不得生成无效 URL；应转换为无链接文本，并由校验报告列出。

同步清单记录：

- 源文件相对路径
- 源内容 SHA-256
- 对应公开文件路径
- 翻译状态
- 最近同步时间

清单不得记录 Wiki 的本地绝对路径。

## 同步流程

1. `npm run wiki:sync` 从配置项或 `LLM_WIKI_PATH` 读取 Wiki 位置。
2. 脚本只扫描允许的三个目录并计算哈希。
3. 脚本输出新增、变化、未变化和待删除页面清单。
4. 新增或变化页面进入待翻译状态，由 Codex 翻译正文、统一术语并转换链接。
5. `npm run wiki:validate` 检查发布边界、元数据、翻译状态和链接。
6. `npm run build` 验证 VitePress 站点。
7. 用户检查 Git 差异后提交并推送，由 Cloudflare 自动部署。

首次同步按同一流程处理当前全部公开页面。后续同步只翻译哈希变化的页面。

## 翻译与人工修改

中文内容以忠实、清晰和术语一致为优先，不要求逐句直译。代码、产品名、协议名和业内常用英文缩写按语境保留。

已发布译文允许人工修改。同步脚本不得直接覆盖已有译文；源文件变化时只标记为待更新，由 Codex 基于旧译文和新原文合并修改。

## 删除策略

源页面消失时，将对应公开页面标记为待删除并在同步报告中列出。脚本不得静默删除。只有明确确认删除后，才更新公开页面、索引和同步清单。

## 失败保护

生成过程使用临时目录。只有所有校验通过后，才替换正式生成结果。任何失败都应保留上一版可发布内容。

以下情况必须使校验失败：

- 出现 `raw/` 引用或 `sources` 字段
- 出现本地绝对路径
- 存在未处理的 `[[wikilink]]`
- 待发布页面缺少中文标题或中文正文
- 内部链接指向不存在的公开页面
- 同步清单与生成文件不一致

## 测试与验收

自动检查包括：

- 允许目录和禁止字段测试
- 哈希变更检测测试
- Wikilink 转换测试
- 断链和绝对路径扫描
- 同步清单一致性测试
- VitePress 生产构建

验收标准：

- 知识库首页能进入三个分类
- 全部公开页面可通过导航或站内搜索访问
- 页面标题和正文为中文
- 内部链接无 404
- 桌面端和移动端均可正常阅读
- 公开仓库不包含原始资料、本地路径或内部来源信息
- 同一份输入重复同步不会产生无意义差异

## 非目标

首版不包含自动翻译 API、`queries/` 发布、原始附件发布、评论系统、在线编辑、语义搜索或 Wiki 到网站的实时同步。
