# Wiki 问答功能 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为已发布的 42 篇中文 Wiki 增加公开的流式问答页面，使用本地关键词检索、DeepSeek V4 Flash、严格每日额度和站内引用。

**Architecture:** 构建阶段把公开 Markdown 转换为确定性片段索引；Cloudflare Worker 仅在 `/api/*` 路径优先运行，其余请求继续由静态资源绑定提供。Worker 依次执行请求校验、HMAC 匿名化、限速、检索、Durable Object 每日额度预留和 DeepSeek 流式调用，再将受控 SSE 与服务端引用返回前端。

**Tech Stack:** VitePress、Vue 3、Cloudflare Workers Static Assets、SQLite-backed Durable Objects、Workers Rate Limiting、Wrangler、DeepSeek OpenAI-compatible Chat Completions、Node.js test runner

### Task 5: Durable Object 严格每日额度

**Files:**
- Create: `worker/daily-quota.mjs`
- Create: `worker/daily-quota.test.mjs`
- Modify: `worker/index.mjs`

- [ ] **Step 1: 写失败测试**

测试同一 UTC 日期内每访客最多 30、全站最多 50；第 31/51 次拒绝；并发 20 个接近上限的 reserve 不能突破 50；日期切换后归零；无效内部请求拒绝。

```js
test('global reservations never exceed 50 under concurrency', async () => {
  const storage = new MemoryStorage({ date, globalCount: 40 })
  const results = await Promise.all(Array.from({ length: 20 }, (_, i) =>
    reserveQuota(storage, { date, visitorKey: `v${i}`, perVisitorLimit: 30, globalLimit: 50 })
  ))
  assert.equal(results.filter(x => x.allowed).length, 10)
  assert.equal(await storage.get('globalCount'), 50)
})
```

测试文件在该测试前定义 transaction-capable `MemoryStorage`，使并发调用经过同一互斥 transaction。

- [ ] **Step 2: 实现 `DailyQuota`**

导出 Cloudflare Durable Object 类和可测试的 `reserveQuota(storage,{date,visitorKey,perVisitorLimit,globalLimit})`。在单个 storage transaction 中读取并更新 `date`、`globalCount` 和 `visitor/${visitorKey}` 状态；只有允许的请求递增。Worker 始终使用 `env.QA_QUOTA.idFromName('global')` 的单例 stub。

在 `wrangler.jsonc` 增加 `QA_QUOTA -> DailyQuota` binding 和 migration `{ "tag": "v1", "new_sqlite_classes": ["DailyQuota"] }`；`worker/index.mjs` 必须导出 `DailyQuota`，以便部署时迁移能找到该类。
